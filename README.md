# Algorithms_lab3 — динамические структуры данных

Практическое занятие №3: стек, очередь, связный список и их применения.
Приложение полностью написано на **C#** с UI на **Avalonia**. Алгоритмы и структуры
вынесены в отдельный доменный проект без зависимостей от UI, поэтому их можно
проверять тестами и использовать отдельно от интерфейса.

## Что реализовано

### Часть 1. Стек на собственном связном списке

`LinkedStack<T>` хранит узлы собственного связного списка и поддерживает
`Push`, `Pop`, `Top`, `IsEmpty`, `Print`.

Протокол команд (по одной в строке `input.txt`):

| Команда | Действие |
|---|---|
| `1,значение` | Push — положить значение в стек |
| `2` | Pop — снять верхний элемент |
| `3` | Top — посмотреть верхний элемент |
| `4` | isEmpty — проверить пустоту |
| `5` | Print — вывести содержимое сверху вниз |

Дополнительно:

* постфиксный калькулятор: `+ - * : ^ ln cos sin tg sqrt abs`, унарный минус;
* перевод инфиксной записи в постфиксную (алгоритм «сортировочная станция» Дейкстры);
* замеры времени для наборов разного размера и состава;
* журнал операций, итоговое состояние и статистика по командам.

### Часть 2. Очередь

Две реализации с общим интерфейсом `IQueue<T>`:

* `LinkedQueue<T>` — собственная очередь на связном списке (голова/хвост, O(1) на
  `Enqueue` и `Dequeue`);
* `StandardQueueAdapter<T>` — обёртка над стандартной `Queue<T>`.

Обе реализации выполняют один и тот же протокол команд: `1,значение`
(Enqueue), `2` (Dequeue), `3` (Peek), `4` (isEmpty), `5` (Print). Результаты
сравниваются автоматически: итоговое состояние, сигнатура результата, количество
операций и ошибок. Замеры выполняются для разных длин и для одинаковых по длине
наборов с разным составом операций.

### Часть 3. Применения структур

* **Цикл в списке — алгоритм Флойда** («черепаха и заяц»). Находит факт цикла,
  его длину, начальный узел и точку встречи за O(n) времени и O(1) памяти.
* **DFS на стеке** — итеративный обход графа в глубину без рекурсии.
  Сложность O(V + E).
* **BFS на очереди** — обход графа в ширину. Вершина помечается обнаруженной при
  постановке в очередь, поэтому каждая обрабатывается один раз. Находит
  кратчайшие расстояния в невзвешенном графе. Сложность O(V + E).
* **BST как динамическое множество** — вставка, поиск, удаление, минимум/максимум,
  высота, обходы (in/pre/post/level order), проверка инварианта.

Графы задаются списком рёбер: `1 2`, `1-2`, `1,2`; одиночное число добавляет
изолированную вершину. Поддерживаются ориентированные и неориентированные графы.

### Часть 4. 12 алгоритмов над собственным связным списком

1. переворот списка на месте;
2. перенос последнего узла в начало;
3. перенос первого узла в конец;
4. подсчёт уникальных значений;
5. удаление неуникальных значений;
6. вставка копии значения после каждого его вхождения;
7. вставка в отсортированный список;
8. удаление всех вхождений значения;
9. вставка перед первым вхождением;
10. присоединение другого списка;
11. удвоение списка;
12. обмен двух узлов по позициям.

### Часть 5. Бинарное дерево из постфиксной записи

`PostfixTree` строит дерево по записи вида `5 3 1 * * 4 * * 8 * *`:
значения задают узлы, `*` отмечает отсутствие потомка. Метки могут быть
числами, буквами или словами; дерево хранит количество узлов, высоту и
число листьев.

## Страницы приложения

1. **Стек** — ввод команд, пошаговый журнал, постфиксный калькулятор и перевод
   инфиксной записи, таблица замеров.
2. **Очередь** — выполнение команд двумя реализациями, сравнение результатов,
   замеры и экспорт в CSV.
3. **Цикл в списке** — визуализация связного списка и шагов алгоритма Флойда.
4. **DFS на стеке** — обход графа, порядок посещения, журнал стека, визуализация.
5. **BFS на очереди** — порядок обхода, расстояния по уровням, журнал очереди,
   визуализация графа.
6. **BST-множество** — операции над деревом, обходы, визуализация.
7. **Операции со списком** — 12 алгоритмов с результатами и пояснениями.
8. **Бинарное дерево** — построение дерева из постфиксной записи и
   визуализация структуры.

## Оценка сложности

| Структура / алгоритм | Операция | Время | Память |
|---|---|---|---|
| Стек на связном списке | Push / Pop / Top / isEmpty | O(1) | O(n) |
| Стек | Print | O(n) | O(1) |
| Постфиксное выражение | Один проход | O(n) | O(n) |
| Инфикс → постфикс | Сортировочная станция | O(n) | O(n) |
| Очередь на списке | Enqueue / Dequeue / Peek | O(1) | O(n) |
| Флойд | Поиск цикла | O(n) | O(1) |
| DFS | Обход графа | O(V + E) | O(V) |
| BFS | Обход графа, кратчайшие пути | O(V + E) | O(V) |
| BST | Вставка / поиск / удаление | O(h), в среднем O(log n) | O(n) |
| Переворот списка | Изменение ссылок | O(n) | O(1) |
| Удаление неуникальных | Проход с HashSet | O(n) | O(n) |
| Бинарное дерево из постфиксной записи | Построение | O(n) | O(n) |

## Методика замеров

Кнопка «Запустить замеры» создаёт текстовые наборы команд во временном каталоге,
читает их с диска и измеряет:

* время чтения файла;
* время выполнения команд;
* суммарное время.

Для очереди отдельно замеряются собственная реализация и `Queue<T>`. Результаты
можно выгрузить в CSV и использовать в отчёте. Чтобы получить устойчивые числа,
запускайте замеры несколько раз и берите медианные значения.
